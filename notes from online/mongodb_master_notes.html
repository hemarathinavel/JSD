Chapter 1: Introduction to MongoDB 🍃

1. What is MongoDB?

  • It is an open-source, document-oriented database.
  • Instead of tables (like traditional SQL), it stores data in a paragraph/document format.
  • Data is strictly stored in the form of Key & Value Pairs (BSON/JSON-like structure).

Chapter 2: Data Structure (Documents) 📦

MongoDB entirely abandons rigid rows and columns. It uses a JSON-like nested structure to group related data. This means a single record can hold complex data types like arrays and nested objects.

1. Standard Document Example

Below is an example of a student document storing varied data types (Strings, Numbers, Arrays/Sets):

var stud = { rno : 1001, name : "Nisanth", age : 21, website : "www.Nisanth.com", hobbies : ["Cooking", "Volleyball"] }

2. Employee Details (Nested JSON format)

A similar Key-Value structure applied to employee records:

var emp = { eno : 1, ename : "Nisanth", esal : 28800.05, designation : "trainer", qualification : "MCA" }
Whenever asked to define MongoDB's internal structure, always explicitly write:
"Data is stored in the form of Key and Value pairs (BSON Format)."

Chapter 3: The Beginner's Bridge (SQL vs MongoDB) 🌉

If you are learning MongoDB for the first time, you must understand how traditional SQL terms map to NoSQL MongoDB terms.

SQL (Relational DB) MongoDB (NoSQL) Explanation (Blue Pen)
Database Database The outer container for the data. (Same term)
Table Collection Instead of a Table of rows, it's a Collection of documents.
Row Document A single record (The JSON object we saw in Chapter 2).
Column Field The "Key" in the key-value pair.

Chapter 4: Core Features of MongoDB ⚡

MongoDB solves the limitations of traditional relational databases through three primary features:

  • 1. High Performance
    Most operations in MongoDB are significantly faster compared to relational databases because data is pre-grouped in documents rather than scattered across normalized tables (no complex JOINs needed).
  • 2. Auto-Replication
    Provides automatic redundancy (Replica Sets). This allows you to quickly recover data in case of a server or hardware failure, ensuring High Availability.
  • 3. Horizontal Scaling (Sharding)
    Sharing (Sharding) is the partitioning of data and placing it on multiple machines.
    Crucial point: It distributes massive datasets in such a way that the order of the data is preserved.

Chapter 5: Practical Commands (CRUD) 💻

To go from scratch to advanced, you must master how to interact with the data. CRUD stands for Create, Read, Update, and Delete.

The Global Syntax:
db.<collection_name>.<operation>({conditions})

1. Create (Inserting Data)

  • Used to add new documents into a collection.
  • Command: insertOne() or insertMany()
// Creating a new employee record inside the "employees" collection db.employees.insertOne({ ename: "Nisanth", designation: "Trainer" })

2. Read (Querying Data)

  • Used to fetch and view data. Equivalent to SQL's SELECT * FROM.
  • Command: find()
// View all employees db.employees.find() // View only employees where designation is "Trainer" db.employees.find({ designation: "Trainer" })

3. Update (Modifying Data)

  • Used to change existing data. You must use the $set operator!
  • Command: updateOne()
// Find Nisanth, and update his salary to 35000 db.employees.updateOne( { ename: "Nisanth" }, // 1. Filter: Who to update? { $set: { esal: 35000 } } // 2. Action: What to change? )

4. Delete (Removing Data)

  • Used to permanently remove a document.
  • Command: deleteOne()
// Delete the employee named Nisanth db.employees.deleteOne({ ename: "Nisanth" })
⚠️ Common Mistake Alert:
When updating a document, beginners often forget the $set keyword. If you omit $set, MongoDB might replace the entire document instead of just updating the specific field!
