MongoDB Basics — Quick Notes

In SQL Server, you have tables with rows and fixed columns. In MongoDB, you have collections with documents (stored in JSON-like format), and documents in the same collection can have different fields — no fixed schema required.

1. Selecting a Database
	use mycompany       // switches to (or creates) a database
db.employees        // refers to the "employees" collection

2. Insert (Create) — like SQL's INSERT INTO

db.employees.insertOne({
  name: "Hema",
  role: "Junior Developer",
  skills: ["ASP.NET", "SQL Server", "Python"],
  experience: 0
})

// Insert multiple documents at once
db.employees.insertMany([
  { name: "Ravi", role: "Developer" },
  { name: "Priya", role: "Tester" }
])

3. Find (Read) — like SQL's SELECT

db.employees.find()                        // gets all documents
db.employees.find({ name: "Hema" })        // like WHERE name = 'Hema'
db.employees.findOne({ role: "Tester" })   // returns only one matching document

4. Update — like SQL's UPDATE
	db.employees.updateOne(
  { name: "Hema" },              // condition (like WHERE)
  { $set: { experience: 1 } }    // field to change
)


5. Delete — like SQL's DELETE


db.employees.deleteOne({ name: "Ravi" })

Key Differences from SQL
SQL Server	MongoDB
Table	                   Collection
Row	                    Document
Column	                    Field
Fixed schema	Flexible/dynamic schema
JOIN	                    $lookup or embedded documents
Primary Key	_id (auto-generated by default)
